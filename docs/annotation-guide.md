# 自采数据标注指南

> 目标：给 `data/annotate/` 里的 **341 帧**画出水体掩膜。
> 这是整篇论文唯一无法自动化的环节，标完就能跑全部实验。

---

## 零、为什么是 341 帧

候选池 1197 帧（1fps 抽帧）→ 抽稀到 401 帧（stride 3）→ 去掉 60 帧缓冲带 → **341 帧**。

- **抽稀到 401**：实测冗余度仍远高于 RivAIrSet（最近邻中位数 0.0766 vs 0.195），
  相对改进 30.9% 几乎没损失。见 `data/processed/field_pool_s3/redundancy__all.json`
- **去掉缓冲带**：train/val/test 切点前后各丢 3 帧，防止相邻近重复帧跨集合造成泄漏

标完这 341 帧，任意策略 / 任意预算 / 任意种子的组合都能自由模拟，
后期加消融实验不用回头补标。

| split | 帧数 | 用途 |
|---|---|---|
| train | 227 | 候选池——选帧策略从这里挑 N 帧 |
| val | 29 | 仅监控，不做早停（样本太少且连续，见下） |
| test | 85 | 最终指标 |

## 二、🔴 本机没有 NVIDIA 显卡，模型必须选轻量版

你的机器是 CPU-only（18 核，无 CUDA）。这不影响训练（实测 CPU 跑完全部实验约
6 小时，挂一晚即可），但**直接影响标注时的交互速度**：

| 模型 | CPU 上每次点击响应 | 341 帧总体验 |
|---|---|---|
| Segment Anything (ViT-B / ViT-H) | 3–8 秒 | 难以忍受 |
| **MobileSAM / EdgeSAM 等轻量版** | **0.3–1 秒** | 流畅 |

**在左侧模型下拉框里挑名字带 `Mobile`、`Edge` 或 `Quant` 的版本**，不要选 ViT-B/ViT-H。
精度差别在水体这种大面积均匀区域上几乎看不出来，而速度差一个数量级。

列表里如果没有轻量版，升级到最新版 AnyLabeling 再看。

## 四、怎么标

### 标签名只能是 `water`

第一次画完多边形，会弹框让你输标签，**输入 `water`**（小写）。
之后它会记住，直接选即可。

> 脚本只认 `water`（大小写不敏感），写成 `Water`、`水`、`river` 都会被忽略，
> 结果就是这帧变成"全图无水"，静默污染数据。

### 用 SAM 的流程（每帧约 30–60 秒）

1. 点工具栏的 `Auto Labeling`（魔棒/AI 图标）进入自动模式
2. 在水面中间**左键点一下** → 模型圈出一块区域，看预览对不对
3. 不准就继续点：
   - **左键**在漏掉的水面上加点 → 扩展选区
   - **右键**在误选的岸边/植被上点 → 排除该区域
   - 通常 2–5 次点击就够
4. 满意后点 `Finish Object`（或按 `F`），弹框输 `water`
5. 边界个别地方不准，退出自动模式，用多边形工具（`Ctrl+J`）手动改点
6. **翻页前扫一眼左侧对象列表，确认有一条 `water`**，再按 `D` 切下一张

> 🔴 **第 6 步不能省。** 如果画完选区没按 `F` 就按 `D`，自动保存会写下一个
> **空 JSON，且不报任何错**。这一帧就变成"整图皆背景"的样本，主动教模型
> "水 = 背景"——比干脆不标还糟。首批 9 帧里有 6 帧栽在这上面。

### 值得记的快捷键

| 键 | 作用 |
|---|---|
| `D` / `A` | 下一张 / 上一张 |
| `F` | 完成当前对象 |
| `Ctrl+J` | 多边形工具 |
| `Ctrl+S` | 手动保存（无水帧要用它） |
| `Ctrl+Z` | 撤销 |
| `Delete` | 删除选中的多边形 |

### 几种要注意的情况

| 情况 | 怎么处理 |
|---|---|
| 一帧里有多块分离水面 | 画多个多边形，都标 `water` |
| 整帧没有水 | **不画任何多边形，但仍要保存**（按 `Ctrl+S`）——它是合法负样本 |
| 岸边湿地 / 浅滩分不清 | 以**连续水面**为准，判不准就按你的一致标准来，重要的是前后一致 |
| 水面有反光 / 白亮斑 | **算水体**——反光是本文重点研究的难度维度，不能因为看不清就排除 |
| 水面有桥、船、植被遮挡 | 遮挡物**不算水体**，从多边形里挖掉或分开画 |
| 芦苇丛边缘的深色带 | **算水体**——那是芦苇投在水面上的影子，边界画在**芦苇秆根部** |

### 🔴 芦苇边缘：边界画在秆根，不是画在阴影带内侧

本场景的芦苇丛外侧总有一条深色带，透过它能看见水下的秆子——**那是水**。

SAM 按亮度分割，大概率会把这条带子排除，给出的预览贴着亮水面走。这时：
**在深色带上补一个左键点**逼它包进来；还不行就 `Ctrl+J` 进多边形编辑把点往外拖。

为什么这条单独拎出来讲（普通的边界偏差本来是能容忍的）：漏掉的是
**阴影里的水**，而条件 C 整组是暗光拍摄（ISO 1969，比 A/B 暗 19 倍）。
在 A/B 上教模型"暗 = 非水"，偏差会顺着光照这个自变量传进 C 组结果，
变成与贡献点 2 直接相关的混杂——这类偏差不会像普通系统偏差那样被抵消掉。

好消息是改过来更好标：阴影带的内侧边缘是渐变的，画在哪全凭感觉；
而芦苇秆插进水里那条线是硬边，位置唯一，前后一致性反而更容易保证。

> 关于反光：三个数据集里反光维度的活跃度是 LoveDA 0.008 < RivAIrSet 0.017 <
> 你的数据 0.045。反光帧恰恰是论文要证明方法能挑出来的那类样本，标错会直接
> 削弱结论。

## 五、分批计划（别想一口气标完）

341 帧、每帧 30–60 秒 → **合计约 4–6 小时**。连续标 2 小时以上，
后半段的标注质量会明显下降，而标注不一致正是最危险的噪声来源。

建议分 5 次，每次约 70 帧（1 小时）。文件名是按条件排序的，
直接按左侧列表顺序标会先标完 A 再标 B，**这样不好** —— 万一中途停下，
只有一个条件完整，做不成多条件实验。

**按下面的顺序分批，每批都横跨三个条件**：

| 批次 | 标什么 | 累计 |
|---|---|---|
| 第 1 批 | 每个条件各标前 1/5（A 33 + B 31 + C 16） | 80 |
| 第 2 批 | 各标第 2 个 1/5 | 160 |
| 第 3 批 | 各标第 3 个 1/5 | 240 |
| 第 4 批 | 各标第 4 个 1/5 | 310 |
| 第 5 批 | 剩下的 | 341 |

用 `--progress` 看三个条件的百分比，**保持三个数字大致相等**即可，不用精确。

## 八、给自己留的质检习惯

**每标完 50 帧跑一次这条命令**，两类致命错误它都会自己报出来：

```bash
cd D:/Code/uav-water-seg
python -m src.qc_overlay --input data/annotate --out runs/qc
```

它逐帧打印，并在末尾汇总：

- **`<- 疑似漏标！`** —— 这帧没有任何多边形，但画面里大片像水。
  几乎肯定是忘了按 `F`，必须重标
- **`边界漏标中位数`** —— 超过 3% 会报「偏内」，说明芦苇阴影带被排除了
- 还要自己翻几张 `runs/qc/*_overlay.jpg`：标签有没有写错成非 `water`、
  栈道与成片芦苇有没有被误包进来

边界偏一点没关系，**前后一致**最重要。

标注一致性比标注精度更影响实验结论——因为所有策略用的是同一套标注，
系统偏差会被抵消，而随机的不一致会变成噪声，淹没策略间的差异。
LoveDA 那次就是被方差淹没的，这次别在标注环节重蹈覆辙。
